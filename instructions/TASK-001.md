# TASK-001 · M²AD-Synergy 数据集与实验协议审计

**状态**：待明确启动指令。

## 核查清单

1. 阅读 M²AD 官方论文和官方 GitHub 仓库，记录引用、访问日期及所查版本或提交。
2. 检查数据集真实目录结构，记录来源版本、代表性路径及观察依据。
3. 核实视角和光照的数量及索引方式，记录缺失项和例外。
4. 核实同一视角不同光照图像是否空间对齐，记录判断依据及样本范围。
5. 核实官方训练、验证、测试划分，注明官方是否提供各划分以及划分依据。
6. 核实产品实例 ID 的来源、唯一性及跨划分交集，分析多视角、多光照记录造成的实例泄漏风险。
7. 核实 O-AUROC、I-AUROC、AUPRO 的官方计算方式，明确样本单位、分数聚合方式及 AUPRO 积分范围，并以官方实现或论文为据。
8. 核实 Car、Cube、Doll、Ring 是否适合第一阶段实验，以官方发布的类别、覆盖情况和划分为依据。
9. 核实官方基线方法及其运行依赖，记录代码版本、环境配置与模型权重来源。
10. 检查数据分辨率、存储需求和 GPU 资源需求，注明实测值与估算值。
11. 检查 RTX 3090 和 RTX 4090（24 GB）上的环境兼容性，记录实际验证的硬件和软件版本。
12. 给出可复现的实验环境配置建议，注明版本、安装顺序和最小验证命令。

## 执行边界

任务限于数据集与实验协议审计，不得直接开始 VICAD-Syn 模型开发。严禁使用测试集标签训练或调参。无法核实的条目须记录原因、已有证据和阻塞条件。

## 交付物

将执行结果写入 `reports/TASK-001-REPORT.md`，使用以下十个章节。

1. 任务执行摘要
2. 官方数据来源和论文引用
3. 数据目录结构
4. 数据划分与评估协议
5. 数据泄漏风险分析
6. 基线方法分析
7. 环境配置与兼容性
8. 已完成的验证及其日志证据
9. 未完成事项和阻塞问题
10. 对 VICAD-Syn 研究方案的修正建议

逐项给出可追溯的来源、实际命令、环境、参数、随机种子和结果。区分官方口径、本地实测和估算。
