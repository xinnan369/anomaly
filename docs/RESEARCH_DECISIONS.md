## 2026-11-19 项目启动顺序

先建立文档体系，再由明确指令启动数据集与实验协议审计。M²AD-Synergy 为拟研究协议，Car、Cube、Doll、Ring 为待核实的候选类别。DINOv2 ViT-B/14 为基础模型候选，项目章程中的四项方法均处于待验证状态。当前没有已验证的算法决策。

后续每项重要算法变更应记录日期、任务 ID、变更内容、理由、证据、对评估协议的影响及对应报告或提交。证据不足的结论标注为待验证。

## 2026-11-19 · TASK-002 第一阶段环境和基线

- 选用 WSL2 Ubuntu 22.04 和独立的 Python 3.11.11 环境，优先验证本机 RTX 3090。选用已有 CUDA 12.1 可运行记录的 PyTorch 2.2.2，保留上游 README 的 Python 3.9 / PyTorch 2.1.2 组合为尚未复测的参考环境。
- 优先检查 Dinomaly，因为它与研究候选共享 DINOv2 ViT-B/14 骨干，官方配置指定有四个 register token 的版本。INP-Former 使用同一注册版骨干，先核对配置和依赖入口。
- 固定 TASK-001 已审计的官方提交和发布清单。Car 试运行用两个互不重叠的官方训练正常实例，保持官方预处理、模型、损失、优化器和单图打分。阶段一只验证一次更新和留出图推理，正式 Synergy 数据划分、融合定义和评估留待独立验收。

## 2026-11-19 · TASK-002 第二阶段复现协议

- WSL2 上新建 Python 3.11.11 venv，按现有 87 项锁文件安装。与实装版本逐项比对通过，沿用原锁文件。实测设备为 RTX 3090，RTX 4090 兼容性仍待实测。
- 固定上游 `a606aa0e1614f23dad70da26430dd66095192141`、发布 `05abc5d03167354a7ef98541236b5c0bd00abadf` 与 Meta 的 DINOv2 ViT-B/14 reg4 权重。按 Car、Cube、Doll、Ring 顺序先执行 Dinomaly 再执行 INP-Former，每组要求该类完整档案通过 SHA-256、路径及 CRC 检查。数据划分沿用官方清单。
- 正式入口使用官方 100 epoch、batch 12、预处理、模型、损失、优化器、打分及 Synergy 评估。外部启动器将第 50 和第 100 epoch 的内联测试替换为上游已有的空评估。各组从第 100 epoch 的冻结检查点运行独立的官方评价，先验证 Car/Dinomaly，再顺序执行其余七组。外部启动器关闭逐图渲染并保留原始数组，公式和评估样本集合按官方实现执行。
- 子组诊断用固定版本的 `Evaluator` 在最终推理输出上计算。逐视角和光照报告标明各自输入及无定义的组，方法比较等待完整数据，测试集结果不得用于选择参数或检查点。

## 2026-11-19 · TASK-002 实例身份与闭环顺序整改

- 以官方的物件身份 `(object_name, cls_name, object_anomaly)` 和视角身份 `(object_name, cls_name, view, object_anomaly)` 重建期望组。官方输出不带完整身份且顺序由集合遍历决定，因此在相同显示类名与名称下对分数、标签、热图和掩膜一对一匹配，保留重复条目。
- O-AUROC 使用物件标签。I-AUROC 和原图诊断的样本真值取评价尺寸下的掩膜存在性，AUPRO 使用掩膜连通区域。输出保留图像级元数据标签与掩膜真值的计数和分歧，只有单一掩膜标签的子组记空值。
- 先完整训练并评价 Car/Dinomaly 验证工程流程，后续配置仍由固定上游确定。最终检查点需匹配固定源码、配置 SHA-256、模型、类别、发布版、权重哈希、100 epoch 和 30,000 次迭代，且须由训练完成记录绑定其路径和 SHA-256。
